## 0. 実装AIへの最初の指示（これを読んだら最初にやること）

1. **必ず本ディレクトリを 00 → 09 の順に通読してから着手すること。** 部分読みで実装を始めない。
2. **[`08_実装フェーズ計画.md`](08_実装フェーズ計画.md) の Phase 0 から順に実装する。** フェーズを飛ばさない。
3. 各フェーズは **受け入れ基準（AC）を全て満たしてから次へ進む**。ACは [`09_受け入れ基準とテスト.md`](09_受け入れ基準とテスト.md) にある。
4. **仕様に書かれていない判断が必要になったら、`docs/DECISIONS.md` に「日付・論点・採用案・理由」を追記してから実装する。** 黙って決めない。
5. **仕様と矛盾する実装をしたくなったら、実装せずに先に相談する。**
6. UIを書く前に必ず [`06_UI仕様.md`](06_UI仕様.md) と `元/hallmark/skills/hallmark/` を読む。トークンを無視した色・フォント直書きは禁止。

### 絶対に破ってはいけない不変条件（Invariants）

| # | 不変条件 |
|---|---|
| I-1 | **AI接続はOpenAI API互換のみ。** ベンダ固有SDKを入れない（`openai` 互換HTTPクライアント1本で統一）。 |
| I-2 | **オフラインで壊れない。** ネットワーク不通時、取り込み済みソースの閲覧・検索・エクスポートは全て動く。 |
| I-3 | **原本を破壊しない。** `sources/` 配下の原本ファイルはアプリが書き換え・削除しない（プロジェクト削除時を除く）。 |
| I-4 | **APIキーを平文でDB/JSONに書かない。** OSキーチェーン（Tauri `stronghold` もしくは `keyring` crate）に保存し、DBには参照IDのみ。 |
| I-5 | **回答には必ず引用（citation）が付く。** RAG応答は引用不能なら「ソースに根拠なし」と明示する。 |
| I-6 | **エクスポートは `schemaVersion` を持ち、旧版を読める。** マイグレーションは前方向のみ、非可逆な変換は禁止。 |
| I-7 | **Studioのコマンド実行はプロジェクトサンドボックス外に出られない。** 詳細は [`05_AI層とRAG.md`](05_AI層とRAG.md) §7。 |
| I-8 | **ライセンスはMIT。** GPL/AGPLの依存を持ち込まない（LGPLの動的リンク・別プロセスは可、判断は [`07_設定_i18n_配布.md`](07_設定_i18n_配布.md) §5）。 |

## 2. 草案からの確定事項・変更点（実装AIは必読）

草案には仕様上の曖昧さ・矛盾が含まれていた。以下の通り確定した。**草案と本手順書が食い違う場合、本手順書が優先する。**

| # | 草案の記述 | 問題 | 確定 |
|---|---|---|---|
| C-1 | 「Geminiによる画像解析」「Geminiへ入力」 | AI章では「OpenAI API互換のみ」とあり矛盾。Geminiはネイティブでは非互換。 | **パイプラインはモデル非依存。** 草案の「Gemini」は「設定されたVisionモデル」と読み替える。Gemini利用はOpenAI互換エンドポイント（`/v1beta/openai/`）経由でのみサポート。 |
| C-2 | 「画像に関しては標準でどのモデルも対応しているものとする」 | 事実に反する。ローカルの小型モデルは大半がVision非対応。 | **プロファイルごとに `supportsVision` フラグを持つ。** 非対応時は画像を送らずOCR/キャプションのテキストのみで代替し、UIに「Vision非対応のためテキストのみで回答」と表示する。 |
| C-3 | 「Live illustrater」 | 綴り誤り。 | **正式名は `Live Illustrator`。** 日本語UIでは「ライブ解説」。識別子は `live_illustrator` / `liveIllustrator`。 |
| C-4 | 「（ホームタブの）**左側**にどんどんタブを追加していく」 | ホームタブが「一番左」かつ「閉じられない」と直前に定義済み。左に追加すると矛盾。 | **ホームタブの右側に追加**。ホームタブは常に最左で固定・クローズ不可。 |
| C-5 | RAGの実現方法が未定義（埋め込み・検索の記述なし） | 実装不能。 | **ローカル埋め込みを既定**（`fastembed-rs` / multilingual-e5-small）。OpenAI互換 `/v1/embeddings` があればそちらを優先選択可。検索は **BM25(FTS5) + ベクトル のハイブリッド + RRF**。詳細 [`05_AI層とRAG.md`](05_AI層とRAG.md)。 |
| C-6 | 「MCPを利用した資料作成モード」 | MCPのトランスポート・権限が未定義。 | **stdio と Streamable HTTP の2トランスポートに対応。** ツール実行は既定で都度承認、サーバ単位で「常に許可」設定可。 |
| C-7 | Whisper `large-v2` を選択肢に含む | large-v2 は約3GBあり、既定同梱は不可能。 | **モデルは同梱せずアプリ内から都度ダウンロード。** 既定推奨は `small`。ディスク容量チェックと再開可能ダウンロードを実装。 |
| C-8 | 「動画は文字起こしして全て音声とする」 | 映像情報が捨てられる。 | **音声は草案通り文字起こし。加えてキーフレーム（シーン変化検出）を静止画ソースとして副次生成し、時刻でトランスクリプトと紐づける。** Vision非対応時はスキップ。 |
| C-9 | 対応形式に「表計算、md、txt、JSON、JSONL、webサイトリンク、コードファイル」 | 具体的な扱いが未定義。 | [`04_取り込みパイプライン.md`](04_取り込みパイプライン.md) §6〜§9 で個別に確定。 |
| C-10 | 「ある程度の仕様変更に耐えうるように（バージョンタグ）」 | 曖昧。 | **`schemaVersion` を semver で持ち、`migrations/` に前方向マイグレーションを置く。** 未知のマイナー版は警告付きで読み込み、未知のメジャー版は拒否。 |

## 4. 用語（本手順書を通じて統一）

| 用語 | 意味 |
|---|---|
| **Project（プロジェクト）** | ソース群・スレッド・Studio作業領域を束ねる最上位の単位。1プロジェクト = 1フォルダ。 |
| **Source（ソース）** | プロジェクトに取り込まれた原本ファイル（PDF/画像/音声/動画/表計算/テキスト/コード/Webリンク）。 |
| **Document（ドキュメント）** | ソースを解析して得られる「ページ／スライド／発話ブロック／シート／画像」といった中間単位。引用の最小の見出し単位。 |
| **Chunk（チャンク）** | 検索インデックスの最小単位。1 Document は 1 個以上の Chunk を持つ。 |
| **Locator（ロケータ）** | 引用位置。`{page: 12}` `{tStart: 91.2, tEnd: 104.8}` `{bbox: [...]}` `{sheet:"Q1", range:"A1:D20"}` など種別ごとに構造が違う。 |
| **Viewer（資料を見るタブ）** | 草案の「1 資料を見るタブ」。File explorer + プレビュー。編集不可。 |
| **Studio（Studioタブ）** | 草案の「2 Studioタブ」。RAGチャット + MCP + ファイル生成。 |
| **Live Illustrator** | 閲覧中ページを逐次解説する機能。オン/オフ可能。 |
| **File Modifier（ファイルモディファイヤ）** | プロジェクトに属さない単発のファイル変換ユーティリティ。 |
| **Thread（スレッド）** | 会話の永続単位。Live Illustrator はソース×ロケータ単位、Studio はタブ単位。 |
| **Artifact（アーティファクト）** | Studio がワークスペース内に生成したファイル。 |
