### レイヤ規約

- **フロントはビジネスロジックを持たない。** チャンク分割、検索、プロンプト構築、ファイル操作は全てRust側。
- **Rustはフロントの都合を知らない。** IPCコマンドはドメイン用語で定義する（`viewer_open_tab` ではなく `project_add_viewer_tab`）。
- **ファイルパスはフロントに渡さない。** フロントが扱うのは ID と、Tauri の `asset:` プロトコル経由の限定URLのみ。生の絶対パスをWebViewへ渡すことを禁止する（パス漏洩・任意ファイル読み出しの防止）。

## 4. IPCコマンド一覧（契約）

**命名規則**：`<domain>_<verb>[_<object>]`、すべて snake_case。すべて `Result<T, AppError>` を返す。

`AppError` は以下の形で統一する：

```rust
#[derive(Serialize, ts_rs::TS)]
pub struct AppError {
    pub code: String,      // "SOURCE_UNSUPPORTED_FORMAT" 等、安定した識別子
    pub message: String,   // i18nキーではなく英語の技術メッセージ（ログ用）
    pub i18n_key: String,  // UI表示用のキー "error.source.unsupported"
    pub details: Option<serde_json::Value>,
    pub retriable: bool,
}
```

## 5. イベント（Rust → フロント）

`tauri::Emitter` で発火。ペイロードは全て `{ streamId?, jobId?, ... }` を持つ。

| イベント名 | ペイロード |
|---|---|
| `job://progress` | `{jobId, projectId?, sourceId?, kind, phase, done, total, message?}` |
| `job://done` | `{jobId, result}` |
| `job://error` | `{jobId, error: AppError}` |
| `stream://delta` | `{streamId, kind: "text"\|"reasoning", text}` |
| `stream://tool_call` | `{streamId, callId, server, tool, args}` — 承認待ち |
| `stream://tool_result` | `{streamId, callId, ok, preview}` |
| `stream://citations` | `{streamId, citations: Citation[]}` |
| `stream://done` | `{streamId, usage?}` |
| `stream://error` | `{streamId, error: AppError}` |
| `source://status` | `{projectId, sourceId, status, error?}` |
| `settings://changed` | `Settings` |

**キャンセル規約**：フロントは `*_cancel(streamId)` を呼ぶ。Rust側は `tokio_util::sync::CancellationToken` で伝播し、必ず `stream://done`（`cancelled: true`）を最後に出す。イベントが出ないまま終わることを許さない。

## 6. 型の同期

`src-tauri/src/domain/` の型に `#[derive(ts_rs::TS)]` を付け、`cargo test export_bindings` で `src/ipc/types.gen.ts` を生成する。
**手書きのTS型でIPCペイロードを定義することを禁止する。** CIで生成物の差分をチェックし、差分があれば失敗させる。

## 7. エラーとリトライの方針

| 分類 | 例 | 挙動 |
|---|---|---|
| ユーザー起因 | 未対応形式、壊れたZIP | 即座にUIへ理由を出す。リトライ不可 |
| 一時的 | AIエンドポイント 429 / 5xx / タイムアウト | 指数バックオフで3回まで自動リトライ（初回1s、上限8s、ジッタ付き）。それでも失敗ならUIに「再試行」ボタン |
| 設定不足 | 埋め込みモデル未設定、Whisperモデル未DL | ブロッキングせず、その場で設定へ誘導するインラインCTAを出す |
| 致命的 | DB破損 | 起動時に `PRAGMA integrity_check`。失敗したらバックアップからの復元を提案する |

**AI応答の失敗は取り込み済みデータを壊してはならない。** 解析パイプラインでAI呼び出しが失敗した場合、テキスト抽出までの結果は保存し、`status = ready_partial` として、AI由来の情報だけ後から補完できるようにする。
