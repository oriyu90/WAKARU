# 03 · データモデル

## 1. 方針

- DBは2種類。**`app.db`（アプリ全体）** と **`project.db`（プロジェクトごと）**。
- プロジェクトは**フォルダ単位で自己完結**する。`project.db` を含むフォルダをZIPすればそのまま持ち出せる（FR-P2, FR-P3）。
- `app.db` はプロジェクトの**インデックスと設定だけ**を持つ。プロジェクトの中身を持たない。
- 全ID は **UUIDv7**（`uuid` crate, feature `v7`）。時系列ソート可能で衝突しない。
- 全タイムスタンプは **UTCのISO-8601文字列**（`2026-07-31T04:12:00.123Z`）。ローカル時刻で保存しない。
- SQLiteは `PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA synchronous=NORMAL; PRAGMA busy_timeout=5000;`

## 2. プロジェクトフォルダ構造

草案「それぞれのプロジェクトのフォルダ内に入れるもの」を具体化したもの。

```
projects/<project_id>/
├─ manifest.json           ← スキーマ版・プロジェクトメタ（ZIPのルートにも入る）
├─ project.db              ← ソース・チャンク・埋め込み・スレッド
├─ sources/                ← 【原本】アプリは読むだけ。書き換え禁止（I-3）
│   └─ <source_id>/<元のファイル名>
├─ derived/                ← 【解析後・AIが読める形】草案の中核要件
│   └─ <source_id>/
│       ├─ index.json           ← このソースの派生物の目録
│       ├─ document.md          ← ソース全体をMarkdown化したもの（人もAIも読める正）
│       ├─ pages/               ← PDF/スライド/動画キーフレーム
│       │   ├─ 0001.webp        ← ページ画像（Visionモデルに渡す）
│       │   ├─ 0001.txt         ← 抽出テキスト
│       │   └─ 0001.json        ← レイアウト・表・図の構造化結果
│       ├─ transcript.json      ← 音声/動画：セグメント（開始・終了・話者・テキスト）
│       ├─ transcript.md        ← 同上の読み物形式
│       ├─ analysis.json        ← 画像：OCR/物体/場面/図表構造/レイアウト/全体の意味
│       └─ tables/              ← 表計算・PDF内の表を正規化したCSV
├─ workspace/              ← 【Studioの作業領域】サンドボックスのルート
│   └─ …                       AIが作るファイルはここだけに出る
├─ thumbs/                 ← 一覧用サムネイル（再生成可能。ZIPには含めない）
└─ exports/                ← 自プロジェクトからの出力先の既定
```

> **草案の「Studioの作成物で、自分が『インポート』したもの」** は、`workspace/` にあるアーティファクトを `studio_import_artifact_as_source` した時点で `sources/<new_source_id>/` にコピーされ、通常のソースとして解析・インデックスされる。`workspace/` に置いたままのものはソースにならない。

### `manifest.json`

  "appVersion": "1.0.0",           // 作成したアプリの版（参考情報）
  "project": {
    "id": "0192f1a0-...",
    "name": "量子計算の講義",
    "description": "",

    "updatedAt": "2026-07-31T09:40:11.000Z",

  "embedding": { "model": "multilingual-e5-small", "dim": 384, "normalized": true },

## 3. `app.db` スキーマ

```sql
-- migrations/app/001_init.sql

CREATE TABLE schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
-- ('schema_version', '1.0.0') を必ず入れる

CREATE TABLE projects (
  id           TEXT PRIMARY KEY,
  name         TEXT NOT NULL,
  description  TEXT NOT NULL DEFAULT '',
  color        TEXT NOT NULL DEFAULT 'accent-1',
  dir_name     TEXT NOT NULL UNIQUE,      -- projects/ 配下の実フォルダ名（= id）
  schema_version TEXT NOT NULL,
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  opened_at    TEXT,
  archived_at  TEXT,                       -- NULL でなければアーカイブ済み
  sort_order   INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_projects_archived ON projects(archived_at, sort_order);

CREATE TABLE settings (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                      -- JSON
);

CREATE TABLE ai_profiles (
  id            TEXT PRIMARY KEY,
  name          TEXT NOT NULL,
  base_url      TEXT NOT NULL,             -- 例: https://api.example.com/v1
  api_key_ref   TEXT,                      -- キーチェーンのエントリ名。平文キーは絶対に入れない（I-4）
  default_model TEXT,
  supports_vision   INTEGER NOT NULL DEFAULT 0,
  supports_tools    INTEGER NOT NULL DEFAULT 0,
  supports_embed    INTEGER NOT NULL DEFAULT 0,
  extra_headers TEXT NOT NULL DEFAULT '{}',-- JSON
  timeout_ms    INTEGER NOT NULL DEFAULT 120000,
  created_at    TEXT NOT NULL,
  last_ok_at    TEXT
);

CREATE TABLE model_roles (
  role       TEXT PRIMARY KEY,             -- 'chat' | 'vision' | 'embedding' | 'organizer'
  profile_id TEXT NOT NULL REFERENCES ai_profiles(id) ON DELETE CASCADE,
  model      TEXT NOT NULL,
  params     TEXT NOT NULL DEFAULT '{}'    -- JSON: temperature, top_p, max_tokens 等
);

CREATE TABLE whisper_models (
  name          TEXT PRIMARY KEY,          -- 'base' | 'small' | 'medium' | 'large-v2'
  file_name     TEXT NOT NULL,             -- ggml-small.bin
  size_bytes    INTEGER NOT NULL,
  sha256        TEXT NOT NULL,
  downloaded_at TEXT
);

CREATE TABLE mcp_servers (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL,
  transport  TEXT NOT NULL,                -- 'stdio' | 'http'
  command    TEXT,                         -- stdio 用
  args       TEXT NOT NULL DEFAULT '[]',
  env        TEXT NOT NULL DEFAULT '{}',   -- 値が秘密の場合はキーチェーン参照を入れる
  url        TEXT,                          -- http 用
  enabled    INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL
);

CREATE TABLE mcp_tool_policies (
  server_id TEXT NOT NULL REFERENCES mcp_servers(id) ON DELETE CASCADE,
  tool_name TEXT NOT NULL,
  policy    TEXT NOT NULL,                 -- 'ask' | 'always_allow' | 'deny'
  PRIMARY KEY (server_id, tool_name)
);

-- 全プロジェクト横断検索（FR-N3）用の軽量ミラー。正はproject.db側
CREATE VIRTUAL TABLE global_index USING fts5(
  project_id UNINDEXED,
  source_id  UNINDEXED,
  kind       UNINDEXED,                    -- 'source' | 'chunk' | 'message' | 'artifact'
  ref_id     UNINDEXED,
  title,
  body,
  tokenize = "unicode61 remove_diacritics 2"
);
```

> **日本語・中国語のトークナイズ**：FTS5 の `unicode61` はCJKを分かち書きしない。**取り込み時に、CJKテキストは Rust 側で bi-gram 化した文字列を `body` に格納する**（表示用の原文は別カラム `body_raw` に保持し `UNINDEXED`）。クエリ側も同じ bi-gram 化を通す。これで日本語検索が実用になる。実装は `services/retrieval.rs::cjk_bigram()` に集約すること。

);
CREATE INDEX idx_sources_status ON sources(status);

  analysis   TEXT NOT NULL DEFAULT '{}',    -- JSON。OCR/物体/表/レイアウト等
  UNIQUE(source_id, ordinal)
);
CREATE INDEX idx_documents_source ON documents(source_id, ordinal);

-- ───────── チャンク（検索単位） ─────────
CREATE TABLE chunks (

  text_bigram,
  content = 'chunks',
  content_rowid = 'rowid',
  tokenize = "unicode61 remove_diacritics 2"
);
-- triggers: chunks の INSERT/UPDATE/DELETE で chunks_fts を同期すること

  embedding   FLOAT[384]         -- 埋め込みモデル変更時は再構築（§7）
);

CREATE TABLE embedding_meta (
  id         INTEGER PRIMARY KEY CHECK (id = 1),
  model      TEXT NOT NULL,
  dim        INTEGER NOT NULL,
  normalized INTEGER NOT NULL DEFAULT 1,
  built_at   TEXT NOT NULL
);

-- ───────── スレッド・メッセージ ─────────
CREATE TABLE threads (

  usage      TEXT,               -- JSON: {promptTokens, completionTokens}

-- ───────── Live Illustrator の解説キャッシュ ─────────

## 5. Locator（引用位置）の仕様

引用の互換性を保つため、**Locator は種別タグ付きのJSON**とし、未知のフィールドは無視する（前方互換）。

### 5.1 型

```ts
type Locator =
  | { t: "page";    page: number; bbox?: [number,number,number,number] } // PDF/スライド/DOCX
  | { t: "time";    tStart: number; tEnd: number; speaker?: string }      // 音声/動画（秒）
  | { t: "region";  bbox: [number,number,number,number] }                // 画像内の領域（0–1正規化）
  | { t: "cell";    sheet: string; range: string }                       // 表計算 "A1:D20"
  | { t: "line";    start: number; end: number }                         // テキスト/コード/JSONL
  | { t: "path";    pointer: string }                                    // JSON（RFC6901 JSON Pointer）
  | { t: "anchor";  selector: string; charStart?: number; charEnd?: number } // Webリンク
  | { t: "whole" };                                                      // 分割不能なソース全体
```

### 5.2 `locatorKey`（正規化キー）

Live Illustrator のキャッシュとスレッドの同一性判定に使う、Locator の**安定した文字列表現**。

```
page:12
time:0090.000-0104.800        # 秒を小数3桁ゼロ詰めで固定
region:0.100-0.200-0.500-0.640
cell:Q1!A1:D20
line:120-160
path:/items/3/title
anchor:#sec-2
whole
```

- **時刻は「解説の単位」に量子化する**：音声/動画は連続値なので、そのままだとキャッシュが効かない。**トランスクリプトのセグメント境界にスナップする**こと。任意の秒数をキーにしない。
- `bbox` は小数3桁に丸める。
- 実装は `domain/locator.rs::to_key()` の1箇所のみ。フロントでキーを組み立てることを禁止する。

### 5.3 Citation

```ts
type Citation = {
  sourceId: string;
  sourceName: string;
  documentId?: string;
  chunkId?: string;
  locator: Locator;
  quote?: string;      // 実際に根拠となった原文の抜粋（最大200文字）
  score?: number;
};
```

UIでは `[1]` `[2]` の上付き番号として描画し、クリックでViewerの該当位置を開く。

## 6. エクスポート形式（`.wakaru.zip`）

草案「ある程度の仕様変更に耐えうるように設計すること（バージョンタグ）」への回答。

### 6.1 ZIPの中身

```
<project-name>.wakaru.zip
├─ manifest.json           ← §2 の manifest。schemaVersion は必須
├─ project.db
├─ sources/…
├─ derived/…
├─ workspace/…
└─ README.txt              ← 「これはWAKARUのプロジェクトです」＋復元方法＋アプリURL
```

**含めないもの**：`thumbs/`（再生成可能）、`.DS_Store`、`chunk_vectors` の内容（→ §6.2）。

### 6.2 埋め込みの扱い

埋め込みベクトルは**サイズが大きく、モデル依存で移植性がない**。したがって：

- 既定（`embeddings: "rebuild"`）：ベクトルを含めず、インポート先で再計算する。`manifest.embedding` に元のモデル名を記録。
- オプション（`embeddings: "include"`）：`embeddings.bin`（f32 little-endian の連結）＋ `embeddings.idx.json`（chunk_id順）を同梱。インポート先の埋め込みモデルが一致するときのみ利用し、不一致なら破棄して再計算する。

エクスポートダイアログにこの選択肢を出し、サイズ見積もりを併記する。

### 6.3 バージョン互換ポリシー

`schemaVersion` は semver。インポート時の判定：

| 状況 | 挙動 |
|---|---|
| `major` が現行より**大きい** | **拒否**。「新しいバージョンのWAKARUで作られたプロジェクトです」と表示 |
| `major` が一致、`minor` が現行以下 | `migrations/project/` を順に適用して読み込む |
| `major` が一致、`minor` が現行より大きい | **警告付きで読み込む**。未知のテーブル/カラムは保持したまま無視する（ラウンドトリップで壊さない） |
| `major` が現行より**小さい** | マイグレーションチェーンで昇格。チェーンが無ければ拒否 |

**マイグレーション実装規約**
- ファイル名 `NNN_<説明>.sql`（例：`002_add_source_lang.sql`）。番号は連番、欠番禁止。
- **前方向のみ。ダウングレードは書かない。**
- **破壊的変更を含むマイグレーションは、実行前に `project.db` を `project.db.bak-<version>` へコピーする。**
- 各マイグレーションは1トランザクション。失敗したら全体をロールバックして元の版のままにする。
- `schema_meta.schema_version` を必ず更新する。

## 7. 埋め込みモデル変更時の再構築

ユーザーが埋め込みモデルを変更したとき：

1. `embedding_meta` と新設定を比較。一致すれば何もしない。
2. 不一致なら**全プロジェクトの再インデックスが必要**であることをダイアログで説明し、所要時間の見積もり（チャンク数 × 実測スループット）を出す。
3. 承認されたら：`chunk_vectors` をDROP → 新しい `dim` で再CREATE → バッチ（256チャンク単位）で再計算 → `embedding_meta` 更新。
4. 再構築中も**FTS5だけで検索は動く**（劣化はするが機能停止しない）。UIに「ベクトル検索を再構築中（キーワード検索のみ）」を表示。

## 8. データ削除の完全性

| 操作 | 消えるもの |
|---|---|
| ソース削除 | `sources/<sid>/`, `derived/<sid>/`, `thumbs/<sid>*`, `documents`, `chunks`, `chunks_fts`, `chunk_vectors`, そのソースの `illustrations` と `illustrator` スレッド、`viewer_tabs` |
| Studioタブ削除 | `studio_tabs`, `threads`, `messages`。**`workspace/` のファイルは消さない**（アーティファクトは残す。別途削除UIを用意） |
| プロジェクト削除 | `projects/<pid>/` フォルダ全体、`app.db` の該当行、`global_index` の該当行 |
| プロジェクトアーカイブ | 何も消さない。`archived_at` を立てるのみ |

削除は**必ず「DBの行を消す → ファイルを消す」の順**。逆にすると、ファイルだけ消えてDBに残る不整合が起きる。ファイル削除失敗はログに記録し、起動時のGC（孤児フォルダ掃除）で回収する。
