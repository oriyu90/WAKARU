# 08 · 実装フェーズ計画

## 0. 進め方の規約

- **Phase 0 から順に実装する。飛ばさない。**
- 各フェーズは「そのフェーズだけで**動いて触れる状態**」で終わること。半端な機能を次フェーズへ持ち越さない。
- 各フェーズの受け入れ基準（AC）は [`09_受け入れ基準とテスト.md`](09_受け入れ基準とテスト.md) にある。**AC を全て満たすまで次へ進まない。**
- 各フェーズ末に：`cargo clippy -- -D warnings`, `cargo test`, `npm run typecheck`, `npm run lint`, `npm test` が全て通ること。
- 各フェーズ末にコミットし、コミットメッセージの先頭に `phase(N):` を付ける。
- **不明点が出たら `docs/DECISIONS.md` に記録してから決める。**

### フェーズ依存グラフ

```
P0 基盤
 ├─ P1 プロジェクト＋ソース取り込み(静的形式)
 │   ├─ P2 Viewer（タブ・プレビュー）
 │   │   └─ P4 Live Illustrator ──┐
 │   └─ P3 RAG（検索・埋め込み）───┤
 │                                 ├─ P6 Studio ─ P7 MCP＋サンドボックス
 │   └─ P5 音声・動画（whisper）────┘
 ├─ P8 File Modifier          （P0のみに依存。並行可）
 ├─ P9 設定・i18n・表示（テーマ/モノトーン/サイズ）（P0のみに依存。並行可）
 └─ P10 エクスポート／インポート／アーカイブ（P1に依存）
     └─ P11 仕上げ・配布
```

**P8 と P9 は P1 以降と並行して進めてよい。** それ以外は順序を守る。

## 付録 A · フェーズ横断の技術的負債を作らない約束

以下は「後でやる」を許さない。**そのフェーズで一緒に入れる。**

| 項目 | 理由 |
|---|---|
| 8状態（コンポーネント作成時） | 後から全部に足すのは現実的でない |
| i18nキー（文字列を書くとき） | ハードコードを後から剥がすのは苦行 |
| `rem` 単位（CSSを書くとき） | 表示サイズ機能が後から入らなくなる |
| 色に依存しない状態表現（UIを作るとき） | モノトーン機能が後から入らなくなる |
| キャンセル対応（非同期処理を書くとき） | 後付けは競合状態を生む |
| 引用（AI応答を作るとき） | 後から引用を付けるのは不可能 |
| エラーの `i18n_key` | 後から全エラーを分類するのは苦行 |
| 空状態・読み込み状態 | リストを作った時点で3状態を書く |

## 付録 B · 実装順序の中での「早く触れるようにする」工夫

Phase 3 の完了までAIが一切使えないと、開発者もユーザーもフィードバックを得られない。そこで：

- **Phase 1 完了時点で「AIなし版」として一度触れるようにする**（取り込み → 一覧 → キーワード検索）
- **Phase 2 完了時点で「読むだけ版」として触れるようにする**（タブ + プレビュー）
- **Phase 4 完了時点が最初のマイルストーン**（Live Illustrator が動く = プロダクトの核が成立）

各マイルストーンで実際に自分の資料を入れて使ってみること。**仕様書だけを見て作らない。**
