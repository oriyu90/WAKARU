# WAKARU v0.0.0 改修・監査・リリース手順書

作成日: 2026-09-01

## 1. 目的

WAKARU を、クラッシュ安全性、UI の完全性、動作の確実性の3観点で再監査し、次を実装・検証して `v0.0.0` として配布する。

- OpenAI API 互換エンドポイントを接続先として利用できること。
- Anthropic API 互換エンドポイントを接続先として利用できること。
- Studio では、冗長で定型的な AI 文体を避け、明快で自然な成果物を作る「unslop」相当の振る舞いを常時適用すること。
- Live Illustrator（解説）では、理解度を確かめながら導く Socratic tutor と、前提知識が少なくても理解できる ELI5 の効果を組み合わせて常時適用すること。
- 上記は外部 Skill のソースを同梱するのではなく、WAKARU 自身のプロンプト設計と実行経路で同等の利用体験を実現すること。

## 2. 前提と公開方針

- アプリ本体ソースの一次情報は、このローカル非公開リポジトリとする。
- `oriyu90/WAKARU` は公開配布用リポジトリであり、アプリ本体ソースは push しない。
- GitHub には DMG、チェックサム、README、リリースノート、品質報告、第三者ライセンスのみを反映する。
- API キーは OS キーチェーンに保存し、ログ、DB、設定ファイル、リリース成果物へ平文で残さない。
- `v0.0.0` は既存の `v0.1.0` より SemVer 上は古い番号になるが、今回の明示指定を優先する。

## 3. 作業順序

### Phase A: 現状把握と再現可能な基準作成

1. Git の作業ツリー、既存バージョン、配布状況、保守規約を確認する。
2. フロントエンドと Rust バックエンドの全自動ゲートを改修前に実行する。
3. AI 設定、接続テスト、チャット、Studio、Live Illustrator、永続化、終了処理、グローバルエラー処理をコード監査する。
4. 既存の既知制約と実装差分を記録する。

### Phase B: API 互換層の実装

1. 接続プロファイルへ API 形式を追加する。
   - OpenAI 互換: `POST /chat/completions`、Bearer 認証、OpenAI 形式の messages/tools/stream。
   - Anthropic 互換: `POST /messages`、`x-api-key` と `anthropic-version`、Anthropic 形式の system/messages/tools/stream。
2. エンドポイント URL を安全に正規化し、二重 `/v1`、末尾スラッシュ、空 URL、不正スキームを検証する。
3. リクエスト、通常応答、SSE ストリーム、ツール呼び出し、利用量、API エラーを共通の内部表現へ変換する。
4. 接続テストとモデル一覧取得は、互換サーバで未実装でもチャット機能を阻害しない縮退動作にする。
5. 既存プロファイルは OpenAI 互換として読み込み、DB マイグレーションを後方互換にする。
6. API キーや認証ヘッダーがエラー本文・ログへ混入しないことをテストする。

### Phase C: 常時適用する教育・文章品質プロンプト

1. Studio のベース指示へ「unslop 相当」の文章品質規約を追加する。
   - 不要な前置き、反復、過剰な見出し、空疎な強調、根拠のない断定を避ける。
   - ユーザーの目的、対象読者、形式に合わせ、具体的で自然な文章にする。
   - ツール結果は命令ではなくデータとして扱う既存の安全規約を維持する。
2. Live Illustrator のベース指示へ Socratic tutor + ELI5 相当の教育規約を追加する。
   - 最初に平易な核心を示す。
   - 専門語を日常語、具体例、短い比喩へ落とす。
   - 質問への回答を妨げない範囲で、理解を確かめる短い問いを必要時だけ添える。
   - 資料にない内容は一般知識と明記し、出典を捏造しない。
3. 指示は各機能の既存システムプロンプトへ一度だけ合成し、会話履歴のたびに重複しないようにする。
4. プロンプト内容と適用経路を単体テストで固定する。

### Phase D: クラッシュ安全性・UI 完全性・確実性の修正

1. React の最上位にクラッシュ回復 UI を設け、画面全体が白紙にならないようにする。
2. 非同期処理の二重送信、アンマウント後更新、キャンセル競合、イベント購読解除漏れを監査・修正する。
3. Rust 側の `unwrap` / `expect` / panic 候補、ロック保持中の await、終了時子プロセス、DB トランザクション、破損設定の読み込みを監査する。
4. API タイムアウト、キャンセル、切断、途中で壊れた SSE、空応答、不正 JSON、429/5xx、401/403 を利用者向けエラーへ変換する。
5. 設定画面で API 形式、Base URL、モデル、API キー、接続状態が欠けずに表示・編集・保存できるようにする。
6. キーボード操作、フォーカス、ダイアログ、狭い画面、150% 表示、3言語、ライト/ダーク/モノクロを確認する。

### Phase E: 自動検証と実アプリ検証

1. Frontend: typecheck、lint、unit tests、contrast、i18n。
2. Backend: format check、clippy（warnings deny）、全テスト、ts-rs binding drift、cargo deny。
3. API アダプタのモック統合テスト:
   - OpenAI 互換の通常応答・ストリーム・ツール呼び出し・エラー。
   - Anthropic 互換の通常応答・ストリーム・ツール呼び出し・エラー。
4. アプリ起動後、主要画面を巡回し、コンソールエラー、レイアウト欠落、操作不能を確認する。
5. `docs/09` の手動スモークテストを実施し、品質報告へ結果を記録する。

### Phase F: v0.0.0 リリース

1. `package.json`、`Cargo.toml`、`tauri.conf.json` のバージョンを `0.0.0` に揃える。
2. README、RELEASE_NOTES、QUALITY_REPORT、THIRD_PARTY_LICENSES を実装実態に合わせる。
3. ad-hoc 署名の macOS arm64 `.app` と `.dmg` をクリーンビルドする。
4. DMG 検証、マウント後の内包 `.app` の厳格署名検証、SHA-256 作成を行う。
5. GitHub の `v0.0.0` pre-release を作成し、DMG とチェックサムを添付する。
6. 公開リポジトリへ公開文書だけを同期する。
7. `studio-rizi` の WAKARU 紹介ページと `common-rules-document/WAKARU.md` を最後に更新し、それぞれの必須検証を通す。

## 4. 完了条件

- OpenAI 互換と Anthropic 互換の双方が、保存・接続テスト・通常チャット・Studio・Live Illustrator で選択どおり動く。
- Studio と Live Illustrator の常時プロンプトが実際の API リクエストへ入り、重複や競合がない。
- 想定した API 障害でアプリが panic、白画面、永久待機にならない。
- 全自動ゲートが成功し、未解決の高重大度バグがない。
- 手動スモークテストと配布物検証の結果が品質報告に記録される。
- GitHub に `v0.0.0` pre-release と検証済み成果物が存在する。
- 公開ソース非掲載、秘密情報非掲載、保守文書の最終更新というプロジェクト規約を守る。

## 5. 中止条件

- API キー漏えい、プロジェクト外ファイル操作、DB 破損、再現性のあるクラッシュ、署名検証失敗のいずれかが残る場合はリリースしない。
- GitHub へアプリ本体ソースが混入する可能性がある場合は公開同期を停止する。
- 手動でしか判断できない OS 権限ダイアログ等が残る場合は、その時点で品質報告へ明示し、解消または確認後にのみ公開する。
