# WAKARU 静的機能監査

更新日: 2026-09-01

## 対象

- 資料の取り込み・抽出・検索・閲覧
- Live Illustrator のページ解説と資料質問
- Studio の資料参照、会話、文書作成、保存、成果物管理
- File Modifier のテキスト整理と新規文書保存
- 低性能モデル向けの指示、引用、ツール選択、失敗時の安全性
- ダークテーマの文字色

## 結果

| 領域 | 静的確認 | 補強内容 |
|---|---|---|
| 資料閲覧 | 抽出済み文書をロケータ単位で読み、RAGは最大12件を先行取得する | 資料を system 指示から分離し、命令ではなくデータとして境界化 |
| Illustrator | 平易な二段階説明、誤解の先回り、理解確認、引用解決を常時適用 | ページ本文と質問用抜粋を user message に隔離し、プロンプト注入を抑制 |
| Studio | 検索、全文読取、タブ参照、ファイル読取・作成、成果物永続化を実装 | 低性能モデル向け固定手順と、文書依頼時の `write_file` 必須規則を追加 |
| 新規文書 | Markdown/TXT保存、拡張子補正、保存先作成を実装 | 整理結果が原文の70%未満なら Markdown 保存を停止 |
| UI文字 | 主文字、強調文字、トップバー文字は共通トークン | ダークテーマでは3トークンを正確な白 `oklch(100% 0 0)` に統一。補助・無効・状態表示は意図的に控えめな色を維持 |

## 低性能モデル向けの判定基準

1. system message に資料本文を入れない。
2. 資料境界と質問境界を明示する。
3. 資料内の命令文を実行しないと明記する。
4. 不足時の検索・全文取得と、事実確認の順序を短く固定する。
5. 文書作成要求では完全な内容をファイルへ保存させる。
6. 引用タグはアプリ側で実在する検索結果へ解決し、架空タグを採用しない。
7. 明らかな情報欠落を保存前に止める。

## 回帰テスト

- organizer の資料が system prompt に混入しないこと
- Illustrator の資料が system prompt に混入しないこと
- RAG抜粋が信頼できない資料データと明示されること
- Studio の3言語プロンプトに固定手順とファイル保存規則があること
- `write_file` のツール定義が小型モデルにも明示的で、余分な引数を許さないこと
- ダークテーマの主要文字色が正確な白であること
- 短すぎる整理結果を保存不可とすること

実AIの出力品質は接続先モデル、量子化、コンテキスト長に依存するため、静的検証だけで
「すべての低性能モデルが正答する」とは保証しない。上記は誤読・指示混同・保存忘れ・
情報欠落の主要因を減らし、失敗を安全側へ倒すための実装である。
